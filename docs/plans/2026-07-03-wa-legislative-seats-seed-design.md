# WA Legislative Seat-Role Seed (Design)

Issue: #263
Date: 2026-07-03
Status: Approved (brainstorming)
Depends on: #261 (seat-Role model, shipped)
Coordinates with: #265 (merge existing roles onto seats — separate)

## Goal

Seed the 147 canonical WA legislative seat-Roles introduced by #261, against the
49 `legislative_district` jurisdictions that are already seeded. Produce an
importable JSON seed artifact akin to the jurisdictions seed
(`data/cannabis_observer/2026_06_07-usa_wa-jurisdictions.json`).

Note: `data/cannabis_observer/` is **gitignored** — the jurisdictions seed and
this seat seed are **local data artifacts**, generated and archived on the box,
not git-committed. Only the generator + importer scripts and their tests are
committed.

147 = 49 Senate seats (1 per LD, no qualifier) + 98 House seats (2 per LD,
Position 1 / Position 2).

## Scope decision

**Seed + JSON + importer only.** Re-pointing the existing (idiosyncratic)
legislator Roles' assignments onto these fresh seats is deferred to #265 — it is
a normalization problem, not a deterministic seed: heterogeneous district titles
(`Representative, District 1`, `34th District State Representative`,
`District 47 Representative`), **no Position 1/2 distinction on existing House
roles**, generic multi-district roles (`Representative` w/ 7 assignments,
`Senator` w/ 12), and staff/officer roles (`Secretary of the Senate`, etc.) that
must be excluded. Strategy is **seed-then-merge**: this issue seeds; #265 merges.

## Approach — three artifacts (mirror the jurisdictions pattern)

### 1. Seed file — `data/cannabis_observer/2026_07_03-usa_wa-legislative-seats.json`

Local artifact (gitignored, generated + archived on the box — not committed).
Natural keys only (no PM ULIDs):

```json
{
  "_comment": "147 WA legislative seat-Roles (#263). chamber -> org_wa_legislature_chamber identifier; jurisdiction -> slug; role_type -> slug. Generated by scripts/generate_wa_seats.py.",
  "seats": [
    {"chamber": "usa_wa_senate", "role_type": "state_senator",        "jurisdiction_slug": "usa-wa-ld-1", "qualifier": null,         "title": "Washington State Senator, LD-1"},
    {"chamber": "usa_wa_house",  "role_type": "state_representative", "jurisdiction_slug": "usa-wa-ld-1", "qualifier": "Position 1", "title": "Washington State Representative, LD-1, Position 1"},
    {"chamber": "usa_wa_house",  "role_type": "state_representative", "jurisdiction_slug": "usa-wa-ld-1", "qualifier": "Position 2", "title": "Washington State Representative, LD-1, Position 2"}
  ]
}
```

Reference resolution at import time:
- `chamber` → `organizations.id` via the `org_wa_legislature_chamber` identifier
  (`usa_wa_house` → `01KV6PQGA3Y269YY60KN2XSZAY`,
  `usa_wa_senate` → `01KV6PQH9WE7CEFDAXTDZJP54Y`).
- `jurisdiction_slug` → `jurisdictions.id` (`usa-wa-ld-{N}`).
- `role_type` → `role_types.id` (`state_representative` / `state_senator`).

### 2. Generator — `scripts/generate_wa_seats.py`

Reads the 49 `legislative_district` slugs from the committed jurisdictions seed
JSON, emits the 147-seat file deterministically (Senate seat + House Position 1
+ House Position 2 per LD, in LD-number order). Regenerable, no DB dependency;
its committed output is the archived seed artifact. Title convention:
- Senate: `Washington State Senator, LD-{N}`
- House:  `Washington State Representative, LD-{N}, Position {1|2}`

(`{N}` parsed from the `usa-wa-ld-{N}` slug.)

### 3. Importer — `scripts/seed_role_seats.py`

CLI mirrors `seed_jurisdictions.py` (path arg, dry-run by default, `--execute`).
Resolves `chamber → org_id` and `jurisdiction_slug → jurisdiction_id`, then calls
the existing #261 `src.core.observation.resolve_role(...)` per seat →
`NEW` on first run, `AUTO_ATTACHED` on re-run. Reuses the tested seat
match/insert logic; idempotent by construction. Rejects (and reports) any seat
whose chamber identifier / jurisdiction slug / role_type slug does not resolve.

## Key decisions & rationale

- **Reuse `resolve_role`** rather than a bespoke `ON CONFLICT` upsert: single
  source of truth for seat identity + validation; idempotency for free; avoids
  duplicating the partial-index conflict logic.
- **Chamber by identifier, not ULID**: the seed file stays portable and
  human-readable, matching the jurisdictions slug convention.
- **Generator reads district slugs from the jurisdictions JSON**: keeps the seat
  set in sync with the actual seeded districts; generalizes to other states.
- **Fully-qualified, Washington-prefixed titles**: legible admin/API display
  without a join; querying still uses the structured columns.

## Testing

- Unit: generator emits 147 rows, correct per-LD triple, correct qualifiers
  (Senate NULL, House Position 1/2), Washington-prefixed titles, LD order.
- Integration: importer seeds 147 seats against the test DB; re-run yields all
  `AUTO_ATTACHED` (idempotent); spot-check role_type/jurisdiction/qualifier and
  the split-index identity; unknown chamber/slug/role_type → reported reject.

## Out of scope (→ #265)

Re-pointing existing assignments, title parsing, House Position disambiguation,
staff-role exclusion, generic-role triage, archiving superseded roles.
