# #618: a generated Python client for the public API

Spec: the body of #618, with the operator's 2026-10-06 decisions in scope items
1–2. This plan records the choices the spec left open and the order of work.

## Problem

Every consumer of `/api/v1/*` generates or hand-writes its own client and then
finds the same gaps in the spec: admin routes in it, untyped errors, the
`Authorization: Bearer` default against an `X-API-Key` scheme. archiver#300 is
blocked until power-map ships a client of its own.

## Approach

- **Trim the schema at the source.** `admin_router` is included with
  `include_in_schema=False`, and so is `/ready`. `/openapi.json` is then the
  public contract: `/api/v1/*` plus `/health`.
- **Tell the truth about errors.** A `{detail: str}` model, `ErrorDetail`,
  types `401`/`403`/`429` once on the public router, `404` on each route that
  raises it (and on every detail GET, through `DETAIL_RESPONSES`) and `409` on
  the embedding writes. An AST sweep ties the declarations to the raise sites.
  A custom `app.openapi` (`src/api/openapi.py`) widens `HTTPValidationError`'s
  `detail` to "list or string", because several routes raise a string-detail
  `422`. It also adds an optional `If-None-Match` header parameter to every
  operation that declares `304`, so a generated client can send it.
- **`similarity`.** It stays required and non-null. Every embedding that enters
  the API has been finite and non-zero since #299, so a query vector can never
  produce NaN. A read-only count on prod (2026-10-06) found no stored zero-norm
  vectors. `docs/API_PEOPLE.md` states the 422.
- **Client.** `clients/python/` (`power-map-client`, import name
  `power_map_client`) has the generated tree at `power_map_client/generated/`.
  A hand-written `connect()` returns an `AuthenticatedClient` already set up for
  `X-API-Key`. Nothing else is hand-written; retries, error taxonomy and
  Pydantic bridging stay in each consumer's adapter.
- **Gate.** `clients/python/openapi.json` is the committed snapshot.
  A unit test fails when `app.openapi()` differs from it, and when a fresh
  generation from it differs from the committed tree.
  `scripts/regenerate-client.sh` rewrites both and stamps the client's version.
- **Version and distribution.** The client's version is the app version (now a
  third site in `check_version_sync.sh`). Each release is tagged `vX.Y.Z`.
  Consumers pin by git tag and subdirectory, the way they pin notifier's client.
- **Backstop.** `power-map-openapi-parity.timer`, daily: the live
  `/openapi.json` against the snapshot in the main checkout. It exits 3 on a
  difference.

## Tradeoffs / alternatives

- **A filtered copy of the spec instead of `include_in_schema=False`.** The
  operator rejected this on 2026-10-06, so `/openapi.json` stays the single
  contract.
- **`oasdiff breaking`.** Optional in the spec, and not done here. It needs a Go
  binary on the VM and in the gate. The snapshot diff in the PR already shows
  every change.
- **Generator post-hooks.** They are turned off (`post_hooks: []`) so that the
  committed tree depends only on the snapshot and the pinned generator, never on
  the installed ruff. The tree is excluded from ruff.

## Steps

1. Trim the schema (admin, `/ready`). Move the `_test/` scaffolding route in
   `test_require_scope.py` out of the schema too.
2. Add `ErrorDetail` and declare the errors, with the sweep.
3. Add the custom `openapi()`: widen the 422 and add `If-None-Match`. Give
   `api_root` an `operation_id` and a model.
4. Add `clients/python/`, `connect()`, the regeneration script, the snapshot and
   drift tests, and the consumer tests (unit 401; integration 200/304/410 and
   search).
5. Extend `check_version_sync.sh` to cover the client.
6. Add `check_openapi_parity.py` and the timer units.
7. Docs: COMMANDS, PUBLIC_API, API_PEOPLE, AUDITS, AGENTS.
8. Ship v0.59.0, tag `v0.59.0`, install the timer, check from a scratch
   consumer, file the adoption issues.
