# #877 phase 3: bulk accept, the review queue, and the public API

Design: [`2026-11-24-org-kind-suggestions-design.md`](2026-11-24-org-kind-suggestions-design.md) (accepted): D5 (queue), D6 (the bar), D7 (bulk accept), D9 (public API). Phase 2 shipped Jev (flag on 2026-11-27 17:58Z) and the gold set. The trust set (association, business, government, legislature on `jev-1.14.0`) was approved on 2026-11-27.

## Problem

One org of 1,676 has a kind. Rules suggest one for 232 orgs. Jev is working through the rest: 1,576 were still unanswered at 18:33Z, and the backlog should clear overnight. #303's role classification waits on kinds being set. Suggestions alone change nothing: only an operator decision sets `org_kind_id`.

## Approach

Three PRs, each paused for merge and deploy authorization:

- **3a: bulk accept.** `scripts/accept_classification_suggestions.py --field org_kind`. It is dry by default; you run `--execute` only after reading the dry run. It accepts:
  - a rules answer, by definition (decision C, 2026-11-25);
  - a Jev answer at or above the threshold on a kind trusted for its model.

  Every acceptance goes through `record_decision`, the only writer of `org_kind_id`.
- **3b: the review queue.** `/admin/classification/review` lists every undecided org that bulk accept leaves behind, with one-click actions. The dashboard shows the queue's count.
- **3c: the public API (D9).** `org_kind_slug` and `org_kind_source` on org responses, and a `GET /api/v1/org-kinds` catalog. This is a minor version bump with a client regen. It ships last, once kinds are populated.

## Tradeoffs / alternatives

- **One PR.** Rejected. The bulk accept should run as soon as Jev finishes, and the queue's UI and the public contract each need their own review.
- **Queue before bulk accept.** Rejected. Before bulk accept the queue would list about 1,600 orgs, most of which the script settles.
- **Reading an acceptance's source from its note** (`"accepted rules"`, as the Kind panel does now). Rejected for a public field: a note is free text. 3a adds a column instead (below).

## Steps

### PR 3a: bulk accept

1. **Record which source was accepted (TDD).**
   - **Schema:** `classification_suggestions.accepted_source`. Allowed values are `rules`, `jev` or NULL. It is set exactly when `manual_action = 'accept'`.
     - The column is added with `ADD COLUMN IF NOT EXISTS`.
     - A reconciled CHECK enforces the rule above.
     - A backfill fills existing accept rows from their note. Production has one such row.
   - **`record_decision`** writes the column.
   - **The Kind panel** reads the column instead of the note.
   - *Done when:* the classification and panel tests pass; `apply-schema --test` runs twice cleanly; schema parity passes.
2. **The trust set in code, keyed by model (TDD).** Add `TRUSTED_JEV_KINDS = {"jev-1.14.0": frozenset({...})}` to `classification.py`.
   - A Jev answer from any other model is never trusted. A model change therefore needs a re-score, never a silent carry-over.
   - The design's `JEV_TRUSTED_ORG_KINDS` environment variable is replaced by this committed constant, which is reviewed like code.
3. **`plan_bulk_accept(db)` (TDD, integration).** For each active org with a NULL kind and **no `manual` row at all** (a `clear` is an operator's choice to return the org to the queue, so bulk accept leaves it alone), the outcome is one of:
   - `rules`: rules give a kind, and Jev either agrees or hasn't answered;
   - `jev`: there is no rules kind, and Jev answers a trusted kind at or above `JEV_CONFIDENCE_THRESHOLD`;
   - otherwise **queue**, with a reason:
     - `disagree`: rules and Jev give different kinds;
     - `conflict`: rules return `none` with a conflict note;
     - `low`: Jev's confidence is below the threshold;
     - `untrusted`: Jev answers a kind outside the trust set;
     - `none`: Jev answers `none`;
     - `unanswered`: Jev hasn't answered.

   **Tests:** each branch; a decided org and a cleared org are skipped; an archived org is skipped; a Jev answer from an untrusted model is queued.
4. **The script (TDD).** `scripts/accept_classification_suggestions.py`.
   - **Options:**
     - `--field org_kind`. The only field for now; #303 adds `role_type`.
     - `--operator EMAIL`. Resolved to `app_users.id`, because `created_by` is a foreign key to `app_users`; D7's `bulk:<operator>` string can't be stored. Unknown addresses are refused.
     - `--execute`.
   - **Dry run:** echoes the target and prints:
     - counts by kind × source;
     - counts by queue reason;
     - the Jev backlog still unanswered;
     - **the skim list:** the rules acceptances outside `legislature`, with their names in the terminal only (decision C). Each is marked when it is already in the gold set. Today all 21 (13 business, 8 political_party) are in the gold set, and the reviewed labels agree with the rules on every one.
   - **`--execute`:**
     - calls `record_decision(action='accept', …)` once per org, each in its own transaction, so a stale answer fails only that org;
     - the note is `bulk accept <model>`;
     - prints the same counts after the run.
   - Echoes its target; carries the `_dsn` and AST sweeps.
   - **Tests:** dry run writes nothing; `--execute` sets kinds only through `record_decision`; the write sweep still passes.
5. **Docs.**
   - Amend D7: decision C, the operator foreign key, the trust set keyed by model, the `clear` exclusion and the queue reasons.
   - Add a `docs/RUNBOOKS.md` entry for the run.
   - Patch bump (schema change); deploy on your sentence.
6. **The run (operator-gated).**
   - Once the backlog reads 0: a dry run, posted to #877 as aggregates only.
   - You skim the names.
   - Then `--execute` on your word, and the result goes on #877.

### PR 3b: the review queue

7. **The queue (TDD).**
   - **Query:** `review_queue(db, field, limit, after)` covers undecided active orgs with a queue reason from step 3, plus `clear`ed orgs.
   - **Order:** `disagree` and `conflict` first, then by Jev confidence ascending, ending on `o.id` for a stable order.
   - **Page:** `GET /admin/classification/review`, paginated.
     - **Each row:** the org (linked), the rules answer, Jev's answer with confidence, and the reason.
     - **Actions:** Accept rules, Accept AI, Set other…, Dismiss. They post through `record_decision`; the HTMX partial removes the row, with a `with_flash` fallback.
   - **Dashboard:** a count card linking to the queue.
   - **Pins:**
     - route count and mutation-sweep pins;
     - an a11y sweep entry for the new page;
     - `test_flash_levels` entries if any error flash is added.
   - **Docs:** `docs/ADMIN_PANELS.md` (or `ADMIN.md`) gains the page.

### PR 3c: the public API

8. **Wire fields (TDD).** `org_kind_slug: str | None` (a plain `str`, per #857) and `org_kind_source: str | None` on `getOrg`, `batchGetOrgs` and `searchOrgs`.
   - **Source values:** `rules`, `ai` or `operator`. A `set` is `operator`; an accept takes its `accepted_source`, with `jev` shown as `ai` (vendor-neutral, as on the panel).
   - **Tests:** a decided org, an undecided org, a dismissed org (null/null), and ETag changes when a kind changes.
9. **The catalog.** `GET /api/v1/org-kinds` returns `{slug, display_name, description}` with a conditional GET.
   - **Pins:** `API_ROUTE_COUNT` +1, the conditional-GET pin +1, `_CONDITIONAL_GETS`.
   - **Docs:** `docs/API_ORGS.md`.
10. **Release.**
    - Bump `pyproject.toml` and `package.json` to 0.84.0.
    - `regenerate_client`.
    - Deploy on your sentence, then tag `v0.84.0` at the deployed `main`.

## Open questions / risks

1. **`org_kind_source` values on the wire:** `rules` / `ai` / `operator` (operator, 2026-11-27).
2. **Tribal WSLCB licensees** could be a rules `business` that should be `tribe`. All 13 rules `business` orgs are in the reviewed gold set, and none is a tribe. A licensee added later would show up on the skim list in step 4.
3. **Queue size:** from the first 100 Jev answers, about one in five orgs goes to the queue. That projects to roughly 300 for you to work through by hand. If that is too many, a second trust review of `nonprofit` (which missed the 20-answer minimum in the gold set) is the lever, not a lower bar.
4. **Timing:** the script ships before the backlog clears. Run `--execute` only once the dry run shows 0 `unanswered`, or the queue fills with orgs Jev was about to settle.
