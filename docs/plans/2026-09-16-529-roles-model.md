# #529: the roles model

Design: `docs/plans/2026-09-16-roles-model-design.md` (approved 2026-09-16).

## Problem

The applier cannot apply usa-wa's `roles`. PR A (#527) built archive, restore
and identity-carrying creates, but roles need four things it has not got: an
identity value looked up by slug (role type, district), two partial identity
indexes chosen by a condition (#261), a guard so archiving a role does not
strand live assignments on it, and an owned, pinnable title. Until then usa-wa's
role writes cannot leave the observation API (usa-wa#314), and a new committee
next biennium arrives as a `stale` create that blocks the nightly.

## Approach

Extend the manifest a third time, keeping the applier generic:
- **Identity:** `{column, lookup: {table, from, to}}`, resolved through the
  store's existing `lookup`. A miss is `stale`.
- **`unique_live`:** a list of indexes, each `columns` plus optional
  `when` (`null` / `not_null` on an identity column) and `fold` (`lower`). A
  plain list of names stays valid, so assignments do not move.
- **`dependents`:** table → the columns naming the row. A role archive whose
  live dependents this plan does not archive is a `conflict`.
- **Ordering:** every archiving binding's absences are decided before any
  binding's restores and creates, so the guard can see them.
- **Models:** `desired_roles` and `desired_role_titles`; the qualifier rules
  (#273/#302) stay in the model, on `role_types` flags the export adds.
- **Admin:** a `role.title` slot, with `tracked()` on the two routes that write
  a role's title.

## Tradeoffs / alternatives

- **A role hook in core.** Rejected in the design: a second copy of PM's role
  rules, and the applier's first table-specific path.
- **Splitting creates into a later PR.** Rejected: a new role's assignments read
  `stale` until it lands, which blocks the nightly.
- **Checking the qualifier rules in the applier.** Rejected: the flags are PM
  vocabulary the models can read once exported, and the applier would need a
  guard shape used by exactly one table.

## Steps

Test first, one commit per step, `#529` in each message.

1. **Manifest.** The loader learns `lookup` inside `identity`, `unique_live` as
   a list of index specs (`columns`, `when`, `fold`), and `dependents`.
   Refusals: a lookup missing a key; `when` on a column the index does not
   carry; a `fold` that is not `lower`; an empty `dependents` table;
   `dependents` on a binding that does not archive. `manifest.yml` unchanged
   here. Tests: `test_manifest.py`.
2. **Diff: identity lookups.** `_resolve_identity` resolves a lookup through
   `store.lookup` (one call per table per run), and a value with no row is
   `stale` naming it. Creates carry the resolved id. Tests: unit, with fakes.
3. **Diff: the index list.** `slot_holders` takes the index (columns, fold,
   when) rather than bare columns; the engine picks, per row, the index whose
   `when` its identity meets, and counts rivals per index. Assignments keep
   their single unconditional index. Tests: unit, both indexes and the fold.
4. **Diff: archives first, and the dependents guard.** `diff_desired` decides
   every archiving binding's absences before any binding's restores and
   creates. The guard turns an archive with live dependents this plan does not
   archive into a `conflict` naming the count and up to five ids; the knock-on
   conflict on a create or restore that wanted the slot falls out of the slot
   staying held. Store gains `dependent_ids`. Tests: unit, both directions plus
   the knock-on.
5. **The Postgres store and the writer** (integration tier). `slot_holders`
   with the fold and the index's own predicate; `dependent_ids`. Integration:
   a role re-key (archive plus create) in one verified transaction; the guard's
   conflict before any write; a create whose lookups resolve; the #273/#302
   triggers never reached.
6. **Models and manifest entries.** `stg_usa_wa__roles` gains its columns;
   `desired_roles` and `desired_role_titles`; `export_pm_tables` adds
   `role_types`; `tests/role_create_qualifier_invalid.sql` (warn);
   `schema.yml`; `manifest.yml` gains both tables; the `role.title` registry
   entry lands here, since the drift test wants registry, manifest and dbt
   vocabulary to agree at every commit. Tests: dbt fixtures.
7. **Admin.** The `role.title` slot line and note host, `role` in the overlay
   routes' maps, `tracked()` on `roles_detail.py`'s inline title edit and its
   structural edit, the #498 sweep regex, `overlay_field_unmapped.sql`.
   Tests: endpoint, sweep, browser.
8. **Docs, version and gates.** RUNBOOK_DESIRED_STATE (lookups, the index list,
   the guard, the new warn), ADMIN_OVERLAY (nine slots), version 0.52.0. Gates:
   pre-ship, the integration tier alone, the browser tier alone. Last, a
   read-only rehearsal against production from this worktree, expecting 312 and
   312 no-ops and a changed digest. Plan status set to executed.

## Open questions / risks

- **The restructure in step 4 moves code #527 shipped yesterday.** The
  assignment tests are the guard: they must stay green without edits, and any
  edit to them is a signal to stop.
- **`when` and `fold` stay minimal** — `null`/`not_null`, and `lower`. Anything
  else is refused rather than ignored, so a later index shape fails loudly.
- **The guard counts every live dependent**, including assignments outside the
  producer's scope. That is the point: a curated assignment on a role usa-wa
  retired is a person's decision.
- **The rehearsal may show title updates** if a role's title moved in PM since
  the 2026-09-15 measurement. Updates are unlimited, so it would not block, but
  it changes what the first run writes and belongs in the report.

## Execution notes (small revisions, 2026-09-16)

- **Steps 2 and 3 landed together.** The roles binding a lookup test needs
  declares both indexes, so neither could be exercised alone.
- **Step 1 left a scaffold.** `unique_live` became a list of indexes at the
  loader before the engine could choose between them; the applier refused a
  second index until step 3 replaced it.
- **The warn test is `role_create_pm_would_refuse`**, not
  `…_qualifier_invalid`: a create with no title, or a district without a type,
  is refused by the same class of guard (a NOT NULL and a CHECK), and one rule
  in one place beats two.
- **`when` names a column the create writes**, not one of its own index's
  columns — the title index's predicate is on `jurisdiction_id`, which it does
  not key on. YAML's bare `null` is accepted as the condition's value.
- **Only one admin route pins a title.** The structural editor writes the title
  back unchanged (#497), so it cannot move the slot; it is wrapped anyway, so it
  pins if that ever changes.
- **The assignment fixtures drop the role bindings** (`raw_with_assignments`):
  they anchor a role so a span can resolve it, which a manifest that also diffs
  roles reads as an absent role. A partial dbt build now runs with
  `--indirect-selection cautious`, so a singular test of another family does not
  run against tables that build never made.
- **The digest does not change, so the streak does not restart.** The design
  expected it to: the digest covers a run's *actionable* entries, and the roles
  bindings add only no-ops today, so it stays `800ca30f0d0e…`.
- **Rehearsal (production, read-only, 2026-09-16 14:55Z):** `desired_roles` 312
  no-op and `desired_role_titles` 312 no-op, no creates and no archives; the
  assignment diff unchanged (8,393 no-op, 2 creates, 384 archives; 369 date
  updates); verdict blocked on creates 19 and archives 384. The build is clean:
  113 nodes pass, no warnings — production publishes no role create PM would
  refuse.

## Review round 1 (2026-09-16)

Seven findings, all applied on the branch; the finding number is in each commit
message.

- **One defect (`de542a1`).** `slot_holders` folds a `lower` column when it asks
  the database, but the in-memory slot key did not — so two rows of *one run*
  whose folded values collide were not rivals, and neither was live for the probe
  to find. Two committee roles in one org titled "Member" and "member" both
  planned as creates, and the second INSERT would have raised on
  `uq_role_org_title` mid-transaction: the collision the whole slot accounting
  exists to refuse. `_slot_key` now folds at all four sites that build one.
- **A safety net that would have failed (`2fc2ebe`).** The structural editor
  wraps its write in `tracked()` for the day the form moves a title, but depended
  on `get_admin_user` — and `curation_overlay.created_by` is a foreign key onto
  `app_users`. The first pin it ever wrote would have raised, uncaught. A new
  sweep asserts every `tracked()` route provisions its user.
- **The drop rule was written twice (`b3ff342`)** — in `desired_roles` and again
  in `role_create_pm_would_refuse` — and the two disagreed on row scope. The warn
  now left-joins the model and names the creates it dropped, so they cannot
  drift.
- Three tidying changes: `_diff_absent` no longer takes the `creating` set this
  ordering can never fill (`806341a`); `stg_usa_wa__roles` drops `span_kind`,
  which the design named and nothing reads (`713a2e0`); and the dependents
  guard's `archived_now` side effect — what keeps a blocked archive's slot held —
  is documented (`6018e0c`).
